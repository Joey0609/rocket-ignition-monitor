# 冻结规则复测：用户指定的 10 个投稿

本轮在下载新素材前冻结 `1e94a029bcc9b3e1a8bf424aeffe57096a3adead` 的识别实现。不得根据测试结果修改误报规则、阈值或状态机。人工标注只用于检测结束后的评分，不参与检测、启动窗口或状态重置。

- 用户的 P **从 0 开始**。`sources.json` 同时记录零基 `p0`、网站的一基 `site_page` 和 CID，避免下载错段。
- 10 个投稿、13 个指定分 P。长八遥八 P0～P3 连续拼接，在整段内只创建一次检测器和状态机；其余指定视频从各自开头初始化。
- 长八甲遥三 P1、长十二遥二 P0 属于此前参与过调参的素材，不能当作新盲测。其余 8 个投稿未用于此前调参。
- 原始下载为 480p H.264 视频轨，不含音轨。按 10 FPS 解码为 480×270 图片，每张依次处理；不跳过长时间负样本。
- 本轮没有新增版式适配，沿用已有自动主画面定位和固定 ROI。包装、画中画、切镜、视频自身的延迟仍可能影响结果，不能据此直接声称纯摄像头输入已经验证。
- 不注入人工纠错、不手动重置；确认和自动撤销只记录动作，不执行外部业务指令。
- 每次点火前的确认均计为误报，即使后来撤销。误报锁存到实际点火时，不算一次新的正确确认；不可判定帧单列。

`freeze.json` 保存生产文件 SHA256；`protocol.json` 保存本轮入口脚本校验值与执行约定；`labels.json` 为单人视觉标注，不是发动机遥测时间。初始小火光、白芯或可归因于点火的局部照亮即作为参考，不等待尾焰外露或离架。

## 复现

按 `sources.json` 核对下载文件的 SHA256。长八遥八四段按 P0、P1、P2、P3 的顺序建立 FFmpeg concat 清单，使用 `-c copy -an` 无损合并，命名为 `BV1FWLq6jExV_continuous.mp4`。其余文件名使用 `BV号_P零基序号.mp4`。

在项目依赖环境中运行，例如：

```bash
python benchmarks/frozen_holdout_20261025/replay.py /path/to/BV1cEuCzYEyX_P4.mp4
```

需要并行时，为每个独立任务启动独立进程。同一任务的分 P 不可分别创建检测器。输出保存在本目录的 `runs/`，包含逐图片 CSV、解码错误日志、事件截图与原子写入的 `summary.json`；仅完整解码成功且生产文件校验不变时生成完成摘要。

评分脚本和人工标注与识别入口分离。逐帧编号、时间、动作与摘要计数必须一致；中断的诊断运行不得计为完整通过。确认延迟只表示解码后的视频时间，不包含 RTMP 传输、网页显示或命令执行耗时。

原始视频和逐帧证据私下保留，不在代码仓库公开分发。

## 已完成结果

完整 837,567 张图片：误报 1 次，自动纠正 0/1，正确点火确认 8/10。原识别器、ROI、阈值与状态机未改。详情见[逐项复测报告](../../docs/FROZEN_HOLDOUT_20261025.md)及本目录 `results.json`。

```bash
python benchmarks/frozen_holdout_20261025/audit.py
```

识别入口不会读取 `labels.json`；只有评分脚本读取。复现入口对容器时长与采样时长不一致的文件增加独立完整解码帧数核对，避免把正常时间戳差异误当作截断。天舟十号两次完整检测的 74,020 行预测已逐字节核对一致，生产识别规则不受该完成检查修正影响。
